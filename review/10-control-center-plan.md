# 10 · 控制中心技术方案（方案 C）

> 作者：cc-architect（task-6）　对象：`D:\AI应用\dsh-liquid-glass`（DSH 客户端插件）
> 依据：DSH 宿主/客户端 **实时 Inspect Provider**（Service 目录、Slots 拓扑）+ 本项目已交付审查（01-architecture / 02-ux / 12-prior-art）+ DSH Dock v1.3.3 源码（只取策略，不搬代码）
> 约束：**本文件是唯一写盘产物，未改动任何源码。**

## 1. 能力范围界定（四模块可行性）

**占位结论**：①多工作台管理 = **可行（映射到 DSH Workspace，不碰 profile 目录）**；②插件中心 = **高风险（可只读检索，安装不做）**；③会话维护/自愈 = **不做（有损，红线）**；④系统控制台 = **部分可行（诊断做、日志做、凭据不做）**。

## 2. 架构：客户端 / 宿主分工 + API 清单

**占位结论**：宿主 Node 半体做全部文件/进程访问，客户端只做渲染；沿用现有 39321-39324 端口发现机制，新增路由走**同一端口 + token 闸门**。

## 3. UI 接入点选型与推荐

**占位结论**：推荐 **(a) 复用现有 ⚙ 自制面板体系为主入口**；(c) slots 仅在确有必要时用且必须可失败降级；(b) dockkit 右侧栏不作为首选。

## 4. 安全边界（含「凭据管理做不做」结论）

**占位结论**：**凭据管理不做。** 宿主 HTTP 服务绝不可承载任何密钥读写。

## 5. 里程碑落地顺序（4~6 个）

**占位结论**：M1 服务加固 → M2 诊断面板 → M3 工作台管理（只读→写）→ M4 插件检索 → M5 日志/引擎 → M6 汇总。

## 6. 不可行清单

**占位结论**：凭据管理、会话日志自动改写、插件一键安装、独立进程守护、多 profile 目录编排 —— 均不建议做。
